# jwt_tik_tak_toe_app_and_server_s21_school
# Крестики-нолики
Учебный проект по школе 21 (сервер + клиент + jwt авторизация по ТЗ) + реализация webSocket как доп

В нём есть два приложения:

- `mobail/` — Android-приложение на Kotlin и Jetpack Compose;
- `server/` — сервер на Kotlin, который хранит игры в PostgreSQL.

Смысл такой: приложение на телефоне или эмуляторе — это только интерфейс. Все игры, ходы, история и таблица лидеров лежат на сервере. Клиент отправляет запросы, сервер их проверяет и присылает ответ.

## Как это работает

1. При входе приложение отправляет логин и пароль на сервер.
2. В меню можно создать игру с ботом, игру с человеком или посмотреть список чужих игр.
3. Список игр, история и таблица лидеров загружаются обычными HTTP-запросами.
4. Сама игра идёт через WebSocket. Это постоянное соединение: клиент и сервер могут обмениваться сообщениями в любой момент, а не только в ответ на запрос.
5. Когда игрок нажимает на клетку, приложение отправляет на сервер всю доску. Сервер сам решает, правильный ли ход. Если ход неправильный, сервер присылает текст ошибки, а приложение просто показывает его пользователю.
6. В игре с ботом сервер сам делает ход бота сразу после хода игрока.
7. Когда игра заканчивается, сервер сохраняет результат. Поэтому она появляется в истории и учитывается в таблице лидеров.

Проверок ходов на клиенте почти нет специально: если сервер что-то запретил, клиент покажет именно то, что ответил сервер.

## Запуск

Сервер (нужна запущенная PostgreSQL):

```bash
make server
```

Приложение в эмуляторе:

```bash
make emulator
```

Приложение на телефоне (должна быть включена USB-отладка):

```bash
make phone
```

Проверить, запущены ли сервер и эмулятор:

```bash
make status
```

Остановить сервер и все эмуляторы:

```bash
make stop
```

## Важно: телефон работает через USB

Команда `make phone` делает так, чтобы телефон видел сервер на компьютере.

Телефон не знает IP компьютера. Вместо этого `make phone` выполняет команду:

```bash
adb reverse tcp:8099 tcp:8099
```

Она создаёт туннель по USB: всё, что на телефоне идёт на `127.0.0.1:8099`, adb передаёт на компьютер, где на этом порту работает сервер.

Поэтому:

- пока USB подключён — телефон и сервер общаются;
- выдернул USB — туннель пропал, приложение потеряло сервер;
- подключил USB обратно — нужно снова выполнить `make phone` или хотя бы:

```bash
adb reverse tcp:8099 tcp:8099
```

- уже открытое соединение игры само не восстановится, даже если туннель вернуть. Нужно заново зайти на экран игры.
- Wi-Fi на телефоне в этой схеме не участвует. Даже если телефон и компьютер в одной Wi-Fi-сети, `make phone` всё равно использует USB.

В эмуляторе всё проще: ему USB не нужен, потому что у эмулятора есть специальный адрес `10.0.2.2`, который означает «компьютер, на котором запущен эмулятор». Поэтому приложение в эмуляторе обращается к `10.0.2.2:8099`.

## Откуда берётся адрес сервера

В коде адрес сервера не зашит. Он передаётся при сборке через параметр `apiHost`:

```bash
./gradlew assembleDebug -PapiHost=10.0.2.2:8099
```

Дальше Gradle сам создаёт файл `BuildConfig.java` и кладёт туда это значение. Файл находится здесь:

```text
mobail/tiktak_app/app/build/generated/source/buildConfig/debug/com/example/tiktak_app/BuildConfig.java
```

Этот файл не нужно создавать или редактировать руками. Он появляется после сборки и перезаписывается при каждой новой сборке.

Если параметр `apiHost` не передан, используется значение по умолчанию — `10.0.2.2:8099` для эмулятора.

`make phone` собирает приложение с `-PapiHost=127.0.0.1:8099`, потому что дальше `adb reverse` перенаправляет этот адрес на компьютер.

## Если хочется запустить телефон по Wi-Fi

Можно обойтись без USB-туннеля, если телефон и компьютер находятся в одной Wi-Fi-сети.

1. Узнать IP компьютера в Wi-Fi:

```bash
ipconfig getifaddr en0
```

2. Собрать приложение с этим IP:

```bash
cd mobail/tiktak_app
./gradlew assembleDebug -PapiHost=<IP-компьютера>:8099
```

3. Установить APK на телефон по USB и запустить приложение. После установки USB можно выдернуть.

Важно: в этом случае **не нужно** делать `adb reverse`, а `make phone` использовать нельзя — он снова соберёт приложение с `127.0.0.1`.

Если приложение не видит сервер, скорее всего:

- компьютер и телефон всё-таки в разных сетях;
- роутер запрещает устройствам видеть друг друга;
- сервер доступен только с самого компьютера;
- мешает фаервол на компьютере.

При этом IP компьютера может поменяться после перезагрузки роутера. Тогда приложение нужно пересобрать с новым IP.

## Если выкатывать сервер в интернет

Самый простой вариант — белый IP у сервера:

```bash
./gradlew assembleDebug -PapiHost=<белый-IP>:8099
```

Для этого порт `8099` должен быть открыт снаружи, и сервер должен принимать подключения не только с самого компьютера.

Для нормального прода лучше использовать домен и HTTPS/WSS, а не открывать порт сервера напрямую. Сейчас в `ApiConfig.kt` адреса начинаются с `http://` и `ws://`. Чтобы перейти на `https://` и `wss://`, понадобится небольшая правка: добавить в сборку признак защищённого соединения и выбирать схему по нему. Остальной код при этом менять не нужно — он и так берёт адрес из `BuildConfig`.
